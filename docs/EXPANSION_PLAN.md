# Heart of Africa — Expansion Plan

Original-Mechanics Expansion + High-Resolution Map. This document is the
living plan: it is refined here as work proceeds, and it records decisions
that were made once so they don't get re-litigated. Status per workstream
below.

Also read: `docs/DESIGN.md` (the authoritative game spec), `AGENTS.md`
(operating notes).

---

## 1. Recap & current state (2026-08)

The repo implements the complete six-phase roadmap of `docs/DESIGN.md`:
deterministic clue DAG with solvability proof, survival, markets, rivals,
fast travel, two regions as data, scripted dialogue + optional LLM garnish,
procedural art/audio, save/replay with state hashes, and a **player-view
sim bot** that wins 100 seeds using only in-game information.

Baseline before the expansion: **89 tests** green in both feature configs,
`hoatool validate` clean, CI green. HEAD: `45b5146` (ws0).

## 2. Guiding principles

- **Determinism is the contract.** All new sim systems (treasure gen,
  glossary learning, discovery rewards, rival plans) use named seeded RNG
  streams; presentation (map camera, label placement) never consumes sim
  RNG; every new player action is an `Input` recorded in the replay log.
- **No runtime GIS / network dependency.** Tiled is an *authoring-time*
  tool: its JSON export is committed and transformed offline by `hoatool`
  into runtime data and tiles. Any geography source is documented with
  provenance (`docs/MAP_SOURCE.md`).
- **Offline transforms, committed derived data.** Like `world.png` and the
  art atlas: the authored source is the truth; generated artifacts are
  canonical committed output, regenerated by `hoatool`.
- **Content-linted.** Every new content file is validated by `cargo test`.
- **Simulation never imports macroquad/egui** (unchanged P0 rule).
- **No ECS, no async runtime, no new LLM provider.**

## 3. Architecture separation (expansion spec, Part III)

Three concepts stay independent:

| Concept | Type | Source of truth |
|---|---|---|
| Simulation grid | u32 tiles (48×66) | `content/world.toml` + biome PNG |
| World coordinates | km f64 (`WorldPoint`) | derived: `(tile + 0.5) × 33.3 km/cell` — `src/world/coords.rs` |
| Presentation map | 4096×5632 px, tiled LODs | Tiled-authored geometry + procedural base render |

`KM_PER_CELL = 33.3` → ~1600×2200 km extent (delta → Lake Chad). The two
directions of derivation (sim→world pure function) cannot drift by
construction.

## 4. Save versioning

`SAVE_VERSION = 1` on `Save`; `from_json` rejects others with a clear
message (pre-version saves load as v0 and are rejected, not mis-parsed).
Migrations beyond this must bump the version and be documented here.

### WS1 — High-resolution map ▶ (map-authoring environment: **Tiled**)

**Decision (2026-08): Tiled (mapeditor.org) is the map-authoring
environment.** The current stack's gap is precisely what Tiled provides:
image layers, tile layers, object layers, point/polygon/polyline objects,
custom properties, object references, JSON export. The runtime stays
dependency-free; Tiled output is transformed offline.

#### Authoring pipeline

```
assets/maps/africa-v1/
  africa-v1.tmj        # Tiled JSON export — the authored source (committed)
  base-4096.png        # procedural style-layered base render (hoatool map gen)
  tiles/               # generated LOD pyramid (committed derived data)
    manifest.toml
    level-0/ … level-N/
```

**Base render** — `hoatool map gen <world.toml> <out>` renders the 4096×5632
base procedurally from sim data with styled layers (coastlines, Nile width
incl. delta, floodplain masks, hillshade relief, oases/Chad water, region
boundaries, subtle value-noise terrain texture). Muted 19th-century
expedition-map aesthetic; geographic readability over parchment. It is an
*image layer* in Tiled — the author may paint over it.

**Tiled object layers** (all coordinates in Tiled pixels; custom properties
carry ids and metadata):

| Layer | Objects | Custom properties |
|---|---|---|
| `settlements` | points | `id` (must match world.toml) |
| `landmarks` | points | `id`, `kind` (used by SpatialHints) |
| `regions` | polygons | `region_id` (boundaries, floodplains, danger zones) |
| `rivers` | polylines | `id`, `width`, `navigable`, `seasonal` |
| `routes` | polylines | `id`, `from`, `to`, `modes`, `risky`, `seasonal`, `blocked` |

**Import** — `hoatool map import <world.toml> <africa-v1.tmj> <out-dir>`:
parses TMJ (serde_json; no new runtime dep), converts Tiled pixels → world
km via `MapProjection`, then sim tiles; cross-checks settlement ids and
positions against world.toml within a tolerance; writes runtime content
(routes/rivers as polylines with km lengths via the projection, landmarks,
region polygons) and the tile pyramid + manifest.

**Validation** — `hoatool map validate <manifest>`: tiles present/dims
consistent/levels correct; every settlement/landmark in bounds; route
segments not crossing impassable terrain without an explicit
bridge/ferry/waterway/exception; river navigable segments on water; clue
landmark references resolve; sim extent == visual extent.

**Fixtures & tests**: hand-authored TMJ fixtures in `tests/` (Tiled JSON is
a documented format) covering: import round-trip, px→world→sim correctness,
polyline km lengths, validation failure cases (missing tile, off-bounds
point, route across water).

#### Renderer split (`src/render/map/`)

`camera.rs` (map-mode camera: wheel/± zoom, drag pan, F = player, Home =
known world, Esc = gameplay; smoothing presentation-only — a test asserts
camera inputs never change the save hash), `tile_cache.rs` (LOD selection by
zoom, LRU), `layers.rs`, `labels.rs` (priority + deterministic collision
rejection, halos, no jitter, semantic-zoom detail), `overlays.rs` (fog,
clue sectors, risk patterns, route states). The current `render/map.rs`
(256 lines) is split; the old gameplay-follow camera remains for the normal
view.

#### Geometry & travel

- Routes become polylines: travel time uses **polyline length in km**
  (`hours = km / mode_speed × terrain × weather`), not Manhattan distance;
  previews must exactly match executed cost (tested).
- Rivers become width-class polylines; the Nile reads as a coherent system
  incl. the delta.
- Landmarks + region polygons feed the clue SpatialHints (WS2) and
  per-region weather hooks.
- Fog of war: explored sim cells → sector masks over tiles; learned labels
  persist; rumored/explored/visible states.

**WS1 gate:** `map gen/import/validate` clean on the real content; new
coordinate/label/hit-test/fog tests; camera-input hash-neutrality test;
travel preview == executed; no balance change vs baseline (orchestra bot
suite still green).

### WS2 — Regional knowledge & glossary ⏳

- `content/regions/*.toml`: `RegionKnowledge` (direction/distance terms,
  preferred/disliked gifts, terrain lore, landmark terms, etiquette facts;
  provenance notes inline).
- `SpatialHint` semantics behind clue texts: the diamond graph stores
  semantic facts (`origin landmark, relation, distance band, confidence,
  target kind`); dialogue renders them through the speaker's vocabulary;
  sim/solvability operate on semantics only.
- Progressive glossary: unknown terms appear as spoken; learning sources
  (knowledgeable NPCs, guides, bearings, written notes) add to
  `known_terms` (Save); diary re-interprets **old** entries; every required
  term has a reachable source (1000-seed property test).
- Social preferences: Unknown/Rumored/Confirmed; unknown disliked gift =
  small penalty + taboo revealed, never permanent lockout; confirmed prefs
  in diary/person entry + trade UI; severe penalty only on knowing
  violation; repair via apology/appropriate gift.
- In-game **Expedition Reference** section (no external manual).

### WS3 — Treasure, funding, deadline ⏳

- Seeded `#treasure` stream: 4–8 sites/seed from authored candidate areas;
  each: stable id, world position, treasure item, clue chain with precision
  stages, `requires_tool`, provenance, regional values, rival interest.
- `Input::SearchArea` / `Input::Excavate`: no clue → "too broad" with
  explanation; each clue narrows a deterministic radius/sector; shovel
  gates excavation; readable ground-matching feedback; tomb stays
  brute-force-proof (search targets treasure sites only; tomb validation
  unchanged).
- Cross-region value: `[items.region_value]` / `[items.social_value]` on
  goods; treasure as goods with provenance.
- Funding: `ExpeditionFunding`; report hubs (telegraph offices via WS4
  places); `Input::ReportDiscovery`; one-time reward per discovery; grant
  thresholds; no infinite loop.
- Deadline: 5 in-game years (config `mandate_years`), start `start_year`;
  HUD date + remaining; warnings; expiration = "funding/mandate expired"
  game-over; pacing: bots finish well inside the deadline.

### WS4 — Equipment, waterways, bearings ⏳

- Equipment slots (documented deviation from spec's four): `Tool`
  (shovel/rope/machete), `Vessel` (canoe/felucca), `Camp` (tent), `Survey`
  (map kit), `TravelTool`, `PresentedItem` (transient; presenting never
  unequips travel gear). Effects: canteen = hydration-capacity (not
  creation), shovel gates excavation, rope cuts mountain cost, machete cuts
  dense-vegetation cost, canoe unlocks water travel, tent improves rest,
  survey kit improves search precision/bearings. Effects shown before
  purchase and in travel previews. `Input::Equip/Unequip`.
- Waterways from river polylines: navigable segments, ports, hazards,
  seasonal rules; `Input::Embark/Disembark`; vessel speed along segments;
  portage at cataracts (Aswan first cataract as the authored example);
  standard hourly sim for supplies/ailments.
- Settlement places (`content/settlements/*.toml` `[[places]]`): market,
  food, outfitter, authority, lodging, guide, telegraph, docks; first
  arrival shows only obvious places; `AskForBearings` reveals layout +
  nearby landmarks/routes (persists). Fast UI panel, no walkable town map.

### WS5 — Rivals, diary, integration, balance ⏳

- Rivals on the same travel/economy/treasure rules: modeled routes and
  waterways (no teleports), equipment purchase, treasure pursuit +
  excavation, funding/diplomacy use, legal clue consumption, rumor events;
  named streams only; replay-recorded.
- Diary redesign: sections (Journal / Clues / People / Places / Glossary /
  Treasures / Routes / Reference); full clue entry detail; map pins and
  overlap rendering (via WS1 overlays); `Input::PinClue/UnpinClue`.
- Content lint for all new files; player-view bot extended (glossary
  learning, equipment, bearings, treasure loop); 100-seed balance runs for
  both bots; docs (deviations, README, report); headless acceptance
  captures; three manual seeds (user plays).

### Stage B — simulation-grid refinement 🔒

Deferred to a follow-up pass, once the presentation layer is stable.
Recorded requirements (spec Part III Stage B): bump resolution to ~256×384+
with km-per-cell recalibration, travel-speed recalibration (no 4× travel
time), A*/exposure resampling, save-version bump, pathfinding benchmarks.
